# Kevin's Product Mind

**中文** · [English](README.en.md) · [한국어](README.ko.md)

**吸纳中国互联网大厂产品方法论的产品经理 Agent Skill：把模糊需求推进为有依据的产品判断，写成能评审、能开发、和原型对得上的 PRD。适用于不同市场与语言的产品工作。**

它把需求澄清、方案取舍、原型对照、范围管理和 PRD 写作放在同一个工作流里。信息不足时先给推荐方向与关键缺口；需求已确认时直接成文；需求要分阶段、跨会话推进时，按功能拆解、规则基线、原型对账、逐模块成文的路径走，每一步都落到文件里，不靠模型记忆。

## 能做什么

| 场景 | 主要产出 |
| --- | --- |
| 想法、反馈或需求尚不清楚 | 需求简报、推荐方案、主要取舍与待确认项 |
| 核心方案与本期范围已明确 | PRD、功能规则、主流程、异常结果与验收要求 |
| 已有原型，要写或改 PRD | 页面映射、状态矩阵、规则与原型的逐行对照、原型问题清单，以及与原型对得上的 PRD |
| 需要先出原型 | 原型蓝图（页面清单、状态矩阵、界面形式、文案、禁止出现项），确认后再出页面 |
| 分阶段、跨会话推进的大需求 | 功能拆解、决策基线、阶段收口审计、交接模板，PRD 每轮交付一个模块 |
| 修改或评审已有方案 | 范围内的修订、业务逻辑问题与具体建议 |
| 规划与验证 | MVP、优先级、Roadmap、指标口径和实验方案 |

写作强调条件与处理、规则的唯一归属、输入到页面字段的完整链路，以及产品规则与技术实现的边界。PRD 首先写给人看：读者沿着一个用户任务能一路读下去，跨模块对照的政策（如删除范围）收口成一张表。事实、假设、未知与实际为零分别处理；不把示例数据或未验证效果写成现状承诺。

纯转写、翻译、格式转换和已经确定方案的代码实现不属于本 Skill 的主要用途。用户已有模板、作者样本与当前任务范围仍是重要输入。

当前 Skill 和参考资料以中文编写，可在需求中指定输出语言。英文与韩文 README 是仓库说明和调用模板的翻译，跨语言使用效果需在实际客户端中验证。

## V5.0 新增内容

V5 是一次重构，主要解决 V3 在“原型阶段”和“完整 PRD 阶段”暴露的问题：原型和 PRD 对不上、跨阶段确认过的决定丢失、验收只看数量不看能不能读懂。

- **原型对照**：新增 `references/prototype.md`。有原型作为输入时，先做页面映射、状态矩阵和两张逐行对照表，再写 PRD；原型里看得清的交互引用到具体页面，看不出来的规则写在正文；原型里的临时说明、示例数据、选了没区别的按钮列为原型问题，不写成产品规则。
- **长程推进**：新增 `references/long-project.md`。分阶段需求先做功能拆解，确认过的决定当轮写进决策基线，开工先回读文件；支持阶段收口审计、文件化交接和按功能线分给子代理。
- **冲突不再静默覆盖**：与已落盘决定冲突时，明确改口就照做并登记变更，意图不明才问，不重复确认。
- **可读与收口的平衡**：按规则形态决定写法。只属于一个任务的就地写完，一句话共用规则在各处原样复述，跨对象、跨情况对照的政策收口成表。
- **验收更诚实**：计数、映射、语法通过不能证明“走得通、读得懂”；新增线性可读、收口与口径一致的双向检查。

详见 [V5.0.0 版本说明](https://github.com/Kevin-SHANG/kevins-product-mind/releases/tag/v5.0.0)。

## 安装与使用

下载 (https://github.com/Kevin-SHANG/kevins-product-mind/releases/download/v5.0.0/kevins-product-mind-v5.zip)（[版本说明](https://github.com/Kevin-SHANG/kevins-product-mind/releases/tag/v5.0.0)），解压后，将包含 `SKILL.md` 的完整文件夹放入客户端配置的技能目录，目录名保持为 `kevins-product-mind`。

例如，使用 `~/.codex/skills` 作为技能目录时，最终入口应为 `~/.codex/skills/kevins-product-mind/SKILL.md`。使用其他技能目录时替换路径。目标目录已存在时先保留自己的修改，再更新；按客户端要求重新加载技能或开启新会话。

下文提到的 Skill、参考资料、提示词和脚本都包含在安装包内。

`需求提示词.md` 中的新需求模板如下。复制并填写已知信息，不清楚的可留空；在支持 `$skill-name` 调用的客户端中使用：

```text
请使用 $kevins-product-mind 帮我完成以下产品需求。

需求：［想解决什么问题，为谁解决］
背景与材料：［当前情况、用户反馈、数据、文档或链接］
已有原型：［原型位置；没有可留空。界面与规则冲突时以谁为准］
已定事项与限制：［必须保留的规则、本期不做的内容］
推进方式：［一次写完 / 分阶段推进］
希望产出：［方案建议 / MVP / PRD / 方案评审 / 其他］

先阅读材料，再给出你的判断。信息足够就直接完成；影响方向或正确性的关键缺口集中提问，其余低风险、可逆的细节由你判断。已有决定不重复确认，假设与事实分清，不扩展本次范围。
```

同一文件里还有“阶段交接”模板，用于压缩上下文或开新会话时，把当前阶段、基线文件、第一项任务和禁止事项交给下一个会话。

需要其他输出语言时，在模板后加上相应要求。如果客户端不支持自动加载 Skill，可显式提供 `SKILL.md` 与当前任务所需的参考文件；这种方式的加载与执行效果取决于客户端。

## 辅助脚本

脚本需要 Python 3.10 或更新版本，只使用 Python 标准库；只写 PRD 而不调用脚本时无需安装 Python。各脚本的输入格式见 `--help`。

```bash
python3 scripts/experiment_math.py --baseline 0.10 --mde 0.02 \
  --alpha 0.05 --power 0.8 --allocation 0.5 --sides two --direction increase
```

`mde=0.02` 表示提升 2 个百分点。该例输出每组 3841、总计 7682。计算不包含聚类、序贯检验、多重比较或损耗修正；按流量估算的收集天数不能代替完整实验周期。

```bash
python3 scripts/scan_prd_traces.py PRD.md --allow-codes F-A,Q1 --allow-terms report_id
```

该脚本扫描 PRD 中的过程痕迹、自造编号、英文标识，以及“参考原型图”这类不指向具体页面的裸引用，只报告命中位置，不判定通过；加 `--unfinished` 还会报告“占位、待补、TODO”一类标记。文档术语表已定义的编号和已确认的字段用放行参数排除。命中时退出码为 1。

## 评估与贡献

`evals/evals.json` 提供 34 个评估场景。V5.0 新增 13 个，覆盖依据原型写 PRD、原型与规则冲突、原型更新同步、资产名称落盘与回查、冲突改口、结构性修改回查、新会话交接、逐模块成文、原型蓝图先行、功能拆解先行，以及就地写与收口表的平衡。

这一版的场景实际跑过：用 Kimi K3 与 DeepSeek 作为被测模型共试跑 34 次，新增的 13 个场景首轮通过 8 个，按暴露的问题修正规则后 13 个全部通过；另用一个真实硬件项目的功能线做了新旧版本对照。过程与数字见版本说明。场景文件本身不代表在你的客户端里一定通过，欢迎按自己的环境复跑。

改进规则时，欢迎提交 Issue 或 Pull Request，并附上最小输入、观察到的行为和期望结果。请使用可公开或匿名化的材料，避免加入真实客户数据、账号凭据或内部文档。修改脚本时请同时说明实际运行结果；修改写作规则时请检查原有业务含义是否保留。
