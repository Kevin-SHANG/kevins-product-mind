# Kevin's Product Mind

[中文](README.md) · [English](README.en.md) · **한국어**

중국 주요 인터넷 기업의 제품 기획 방법론을 참고한 제품 관리자용 Agent Skill입니다. 모호한 요구를 명확한 제품 의사결정과 검토·개발에 활용할 수 있는 PRD로 정리합니다. 다양한 시장과 언어의 제품 업무에 사용할 수 있습니다.

## 주요 기능

- 요구를 정리하고 대안을 비교해 MVP와 이번 작업의 범위를 정합니다.
- 흐름, 비즈니스 규칙, 실패 처리, 인수 기준을 담은 PRD를 작성·수정·검토합니다.
- 우선순위, 로드맵, 지표, 실험 설계를 지원합니다.
- 합의된 결정을 유지하고 사실과 가정을 구분하며 범위 변경을 문서 전체에 반영합니다.

정보가 부족하면 권장안과 핵심 누락 사항을 먼저 제시하고, 요구가 명확하면 바로 진행합니다. 기존 템플릿과 요청 범위를 우선합니다. 단순 전사, 번역, 형식 변환, 확정된 설계의 코드 구현은 주요 용도가 아닙니다.

현재 Skill과 참고 자료는 중국어로 작성되어 있습니다. 원하는 출력 언어를 요청할 수 있습니다. 영어·한국어 README는 프로젝트 안내와 요청 템플릿을 번역한 문서이며, 언어별 실행 결과는 사용하는 클라이언트에서 검증해야 합니다.

## V3.0 업데이트

- **명명과 본문 정리:** 본문과 도표에는 업무 명칭만 사용하고 S1, S4-A 같은 코드를 새로 만들지 않습니다. 수정 경위, 초안 대조, 자체 점검 결과는 문서가 아닌 전달 설명에 적습니다.
- **기존 번호 범위 한정:** 현재도 사용 중인 기존 번호만 대응 관계를 남기고, 대체된 초안의 번호는 본문에 가져오지 않습니다. 확인되지 않은 영문 enum 이름은 쓰지 않습니다.
- **전달 전 점검 강화:** 부분 수정 시 문서 전체를 스캔하고, 수정하지 않은 단락에서 발견된 문제는 목록으로 보고해 확인을 받은 뒤 수정합니다.
- **도표 규칙:** 모듈 간 반복되는 요청과 응답은 시퀀스 다이어그램으로 분리하고, 빈도가 낮은 되돌아가기 흐름은 연결 노드로 표시하며 핵심 루프는 끊지 않습니다. 진입·종료 설명은 도표 아래 본문에 적고, DingTalk 문서와 Typora에서 모두 지원하는 Mermaid 문법만 사용합니다.
- **완전한 PRD의 판단:** 제목이 아니라 내용으로 판단합니다. 자세한 내용은 [V3.0.0 릴리스 노트](https://github.com/Kevin-SHANG/kevins-product-mind/releases/tag/v3.0.0)를 참고하세요.

## 설치

`~/.codex/skills`를 사용하는 환경이라면 진입점은 `~/.codex/skills/kevins-product-mind/SKILL.md`입니다. 다른 디렉터리를 사용하면 경로를 바꾸세요. 업데이트 전에 로컬 수정 사항을 보관하고, 클라이언트 안내에 따라 스킬을 다시 불러오거나 새 세션을 시작하세요.

## 요청 템플릿

`需求提示词.md`의 전체 템플릿을 번역한 내용입니다. 알고 있는 내용을 채우고, 모르는 부분은 비워 두세요.

```text
$kevins-product-mind를 사용해 아래 제품 요청을 도와주세요.

요구: [누구의 어떤 문제를 해결하려는지]
배경과 자료: [현재 상황, 사용자 피드백, 데이터, 문서 또는 링크]
확정 사항과 제약: [유지할 규칙, 이번 범위에서 제외할 내용]
원하는 결과물: [권장안 / MVP / PRD / 제안 검토 / 기타]

자료를 먼저 읽고 판단을 제시해주세요. 정보가 충분하면 바로 완료해주세요. 방향이나 정확성에 영향을 주는 핵심 누락 사항은 한 번에 질문하고, 나머지 위험이 낮고 되돌릴 수 있는 세부 사항은 직접 판단해주세요. 확정된 결정을 다시 확인하지 말고, 가정과 사실을 구분하며, 요청 범위를 넓히지 마세요.
```

필요하면 원하는 출력 언어를 추가하세요. `$skill-name` 호출 방식은 클라이언트에 따라 다릅니다. 자동 로딩을 지원하지 않으면 `SKILL.md`와 작업에 필요한 참고 자료를 직접 제공하세요.

## 파일 구성

| 파일 | 용도 |
| --- | --- |
| `SKILL.md` | 진입점, 제약, 참고 자료 선택 |
| `references/decisions-and-planning.md` | 제품 판단, 계획, 검증 |
| `references/prd-structure.md` | PRD 구조, 흐름, 필드, 비즈니스 규칙 |
| `references/prd-style.md` | 명명, 문체, 결과물 점검 |
| `references/prd-cases.md` | 수정 전후 예시와 적용 범위 |
| `references/diagram-layout.md` | 도표 배치, 연결선, 분할, 검수 |
| `scripts/` | 우선순위 점수, 실험 표본 크기 계산, PRD 흔적 스캔 |
| `evals/evals.json` | 행동 평가 시나리오 21개와 기대 결과, 테스트 자료 포함 |

원본 자료의 “SYX”는 작성 방법의 출처 표기로 유지했습니다. 예시의 비즈니스 수치는 원래 상황에만 적용되며, 새 프로젝트의 기본 규칙이 아닙니다.

## 보조 스크립트

스크립트 실행에만 Python 3.10 이상이 필요하며, 표준 라이브러리만 사용합니다. 인수는 `--help`로 확인할 수 있습니다.

```bash
# UTF-8 CSV 헤더: item,reach,impact,confidence,effort
python3 scripts/score_priorities.py priorities.csv --method rice

# 두 독립 비율 실험: 기준 10%, 2%p 상승
python3 scripts/experiment_math.py --baseline 0.10 --mde 0.02 \
  --alpha 0.05 --power 0.8 --allocation 0.5 --sides two --direction increase
```

RICE, ICE, 가중 점수를 지원합니다. `confidence`는 0–1 사이의 소수로 입력하며, 누락된 값은 자동으로 채우지 않습니다. 예를 들어 헤더 순서로 A=(1000,2,0.8,4), B=(2000,1,0.5,5), C=(500,3,1,2)를 입력하면 C=750, A=400, B=200 순으로 정렬됩니다. 결과는 표준 출력 또는 `--output`으로 지정한 파일에 저장됩니다.

실험 예시는 그룹당 3,841명, 총 7,682명을 반환합니다. 정규근사는 군집, 순차 검정, 다중 비교, 이탈 보정을 포함하지 않습니다. 표본 수집 기간만으로 전체 실험 기간을 정할 수는 없습니다.

```bash
python3 scripts/scan_prd_traces.py PRD.md --allow-codes F-A,Q1 --allow-terms report_id
```

이 스크립트는 PRD에서 작업 과정의 흔적, 임의로 만든 코드, 영문 식별자를 스캔합니다. 발견 위치만 보고하고 통과 여부는 판단하지 않으며, 문서 용어집에 정의된 코드와 확인된 필드는 허용 옵션으로 제외합니다. 발견 항목이 있으면 종료 코드 1을 반환합니다.

## 평가와 기여

`evals/evals.json`은 평가 시나리오 21개를 정의합니다. V3.0에서는 초안 번호를 여러 차례의 작성 과정에서 정리하는 시나리오, 유효한 문서 간 코드를 유지하는 시나리오, 흐름도와 시퀀스 다이어그램을 분리하는 시나리오 3개를 추가했고, 복잡한 도표 분할 시나리오에 명명 점검을 보강했습니다. 실제 Agent 환경에서 실행하고 결과를 기록해야 합니다. 파일이 있다는 사실만으로 평가를 통과한 것은 아닙니다.

Issue와 Pull Request를 환영합니다. 최소 입력, 실제 결과, 기대 동작을 함께 제공해주세요. 공개 가능하거나 익명화된 자료를 사용하세요. 스크립트 수정 시 실제 실행 결과를 첨부하고, 작성 규칙을 바꿀 때는 비즈니스 의미를 보존해주세요.
